# 2026-10-04 选择器闪窗定位记录

## 结论

Codex 桌面端的 `mcpServerStatus/list` 状态查询会建立临时 MCP 服务连接，获取工具清单后销毁临时子进程。旧版 `App.OnStartup` 对每次进程启动都立即调用 `window.Show()`，所以每次状态查询都出现一个短暂的选择器；正常聊天的持久 MCP 进程可以同时存在，形成“一个窗口正常、另一个反复闪现”的现象。

## 日志证据

应用日志中，这些临时进程通常依次记录 `app.starting`、`selector.shown`、传输开始读取和 `mcp.host.started`，然后记录结束。未出现应用异常或正常退出事件，Windows Application 日志中也没有匹配的崩溃事件。

将应用时间转换并对照 Codex 的 UTC 日志后，45 次临时进程启动均落在 `mcpServerStatus/list` 请求期间；其中 40 次最后一条记录与状态查询响应相隔不足 1 秒。对应时段当前聊天的 MCP 状态持续为 `ready`。

## 隔离重现

使用独立诊断目录作为 Codex app-server 的配置目录，仅配置 `window-agent`，不创建聊天、不请求模型、不发送目标窗口输入。连续执行两次 `mcpServerStatus/list`：

| 请求 | 耗时 | 临时子进程 PID | 响应后仍存活 |
| --- | --- | --- | --- |
| 第一次 | 3.670 s | 8132 | 否 |
| 第二次 | 2.910 s | 19404 | 否 |

两次均成功返回工具清单，且旧版子进程日志都记录了 `selector.shown`。Codex app-server 在两次查询之间保持运行，最终正常以退出码 0 退出。

另一次直接 MCP stdio 连接检查在 3.075 秒内完成 `initialize`，返回旧版全部 11 个工具。关闭标准输入后，服务写出完整关闭路径并以退出码 0 退出。这排除了该诊断版本必然无法完成握手的假设。

## 修复

- 启动时仅创建隐藏的选择器，工具发现和状态查询不显示 GUI。
- 增加 `show_window_picker` 工具，显示本地人工选择器，不绑定或切换目标窗口。
- 未选择目标时，截图/输入工具自动显示选择器并返回 `no_window_selected`；人类连接目标后再重试。
- 日志文件名加入启动时间，避免 Windows 复用 PID 后混写不同运行。

新版本仍使用单进程 WPF + MCP stdio 架构，窗口选择入口保持在本地 GUI 中。

## 修复后检查结果

自包含 Release `win-x64` 发布完成，目标框架仍为 `net10.0-windows10.0.18362.0`。使用修复版重复相同的隔离查询：

| 检查 | 结果 |
| --- | --- |
| 两次 `mcpServerStatus/list` | 都返回 12 个工具；PID 16140、11356 日志只有隐藏选择器创建，显示次数为 0 |
| 直接 `initialize` + `tools/list` | 返回 12 个工具；选择器显示次数为 0；退出码 0 |
| `show_window_picker` | 选择器显示一次，工具调用成功；退出码 0 |
| 无目标的 `screenshot` | 选择器显示一次，返回 `no_window_selected`；退出码 0 |
| 工具输入 schema | 服务注入参数没有暴露为工具参数 |

这些检查只覆盖协议与选择器生命周期，没有向用户窗口发送鼠标或键盘输入。Codex 的临时查询仍会创建并销毁进程，这是宿主发现工具的行为；新版本消除了该路径的可见 GUI 副作用。

检查报告保存在仓库忽略目录 `.tools\diagnostics`。修复版发布目录为 `artifacts\publish\win-x64-lifecycle`，正在运行的旧 EXE 不会被直接覆盖。

## 可复用的诊断方法

1. 检查 `%LOCALAPPDATA%\WindowAgentMcp\logs` 的应用生命周期。
2. 检查 Codex 本机日志中的 `mcpServerStatus/list` 和 `mcp_server_startup_status_updated`，注意 UTC 与本地时间换算。
3. 将进程启动/最后日志时间与宿主请求区间对齐。
4. 通过独立 MCP 协议连接验证初始化、工具列表和 stdin EOF 的正常关闭路径。
5. 用隔离 Codex app-server 重现状态查询，避免把临时发现进程误判为应用崩溃。

本机 Codex 日志位于 Windows 包虚拟化目录下的 `LocalCache\Local\Codex\Logs\YYYY\MM\DD`。目录元数据在某些上下文显示为零长度，但按具体文件路径读取仍能得到日志；应以读取内容为准。
